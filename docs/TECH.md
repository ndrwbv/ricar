# «Рыцарь» — технические решения прототипа (уровень 1)

## Стек

* **Three.js** (WebGL) — настоящая 3D-геометрия: дома, стены, ванна, машины, любые коробки и цилиндры, а не сетка рейкастера.
* **Vite** — сборка и dev-сервер.
* **Electron** — оболочка для Steam (Windows / Linux / SteamOS / macOS). Steamworks подключается позже через `steamworks.js` в `electron/main.cjs`.
* Внешних ассетов нет: все текстуры, спрайты, гибсы и звуки генерируются кодом при старте (подход перенесён из наработок `2026-08-17-story`). Это не принципиально — любую процедурную текстуру можно заменить PNG, `textures.js` отдаёт обычные `THREE.Texture`.

## Почему не Godot

Godot 4 — хороший выбор для такой игры в продакшене, и если проект пойдёт дальше прототипа, переезд на него разумен: нативный Vulkan/Mobile-рендер, встроенный Steam Input, GDExtension для Steamworks, экспорт под Deck без Chromium в комплекте. Причины, по которым прототип сделан на web-стеке:

1. **Скорость итераций в этой среде.** Каждую правку я вижу в браузере через секунду и могу проверять поведение скриптом. Godot требует редактора для сцен и ресурсов, headless-прогон без визуального контроля не дал бы проверить «как это играется».
2. **Полный контроль над рендером.** Пиксельный вид, инстансинг крови, декали, биллборды — всё в 300 строках без борьбы с материалами и импортом.
3. **Одна кодовая база для Steam и веба.** Демо-страница для витрины Steam или itch делается той же сборкой.
4. **Производительность на этом масштабе не упирается в движок.** См. ниже: на Steam Deck запас по fps многократный.

Что переносится в Godot без переписывания идей: описание уровня (боксы, триггеры, спавны), система разделки (стаггер → казнь, хедшот, разрыв тела), поведение врагов, все процедурные текстуры (перегенерируются в PNG скриптом).

## Производительность (цель: 60 fps на Steam Deck, 1280×800)

* **Внутреннее разрешение 0.5× экрана** (640×400 на Deck) с пиксельным апскейлом через CSS. Клавиша `P` переключает 0.5 / 0.35 / 0.75 / 1.0.
  Растяжение всегда **целое**: размер буфера подгоняется так, чтобы игровой пиксель занимал ровно k пикселей экрана (с учётом devicePixelRatio),
  а остаток в доли пикселя уходит за край. Дробный апскейл давал пиксели разного размера — картинка шла рябью на каждом шаге камеры.
* **Статичная геометрия склеена по текстуре** (`BufferGeometryUtils.mergeGeometries`): весь уровень — ~32 меша, а не сотни.
* **Кровь-капли** — один `InstancedMesh` на 2500 инстансов. **Декали** — инстансы по типам (6 брызг на пол, лужа, 4 брызги на стены, пулевые дыры). **Искры** — инстансы. Гибсы — пул на 90 биллбордов, трупы — пул на 40.
* **Без теней, без постобработки**, тонмаппинг выключен, `MeshLambertMaterial`, ограниченное число точечных источников (факелы, фонари, пул на 4 вспышки выстрелов).
* **Бюджет света** (`World.bindLights`, настройка «Одновременных источников света», по умолчанию 8). Это самая дорогая
  строка в кадре: three компилирует шейдер под фактическое число источников в сцене, и каждый пиксель каждой поверхности
  прогоняет цикл по всем из них — цена растёт линейно, а от расстояния до источника не зависит вовсе. В песочнице стояло
  под четыре десятка факелов и свечей; замер таймером GPU (`EXT_disjoint_timer_query_webgl2`, буфер 1280×800,
  камера в точке появления, лицом к ряду комнат): **3.54 мс на кадр против 1.86 мс** после правки — вдвое,
  а на видах попроще (камера в зале-склепе) — втрое, с 1.44 до 0.49 мс.
  Поэтому источники уровня хранятся как записи, а настоящих `PointLight` ровно столько, сколько разрешает бюджет; каждый
  кадр они перецепляются на самые важные записи (важность — способность осветить то, что видно от камеры). Смена не
  мгновенная: новый разгорается, старый гаснет за 0.2 с, а тот, кто уже держит фонарь, получает фору в оценке — иначе два
  почти равных факела отбирали бы его друг у друга и мигали на каждом шаге. Само пламя рисуется отдельной картинкой
  и видно всегда, даже когда фонарь ушёл соседу.
* Коллизии — свои AABB-тесты, луч против AABB (стены) и цилиндров (враги/игрок), навигация A* по сетке 0.5 м с растеризацией препятствий за 0 мс на старте.
* **Сетка ускорения по XZ (клетка 2 м, CSR-списки)** над всеми solids. Лучи идут по клеткам 2D-DDA и останавливаются, как только попадание
  ближе выхода из клетки; движение и высота пола берут кандидатов из клеток под запросом. На импортированной E1M1 (≈5000 solids) это
  ~2 мкс на луч вместо ~60 — а лучей за кадр сотни: зрение каждого врага, прицел, каждая капля крови щупает пол.
* **A\*** на типизированных массивах с номером поколения вместо двух `Map` на поиск, оценка расстояния — октиль вместо евклида
  (не завышает, путь остаётся кратчайшим, но клеток разгребается втрое меньше). Неудачный поиск ставит бойцу паузу: раньше
  `!path` означало «искать снова тем же кадром», и десяток врагов, которым до героя не дотянуться, съедали кадр целиком.
* `magFilter = Nearest` + **мипмапы с анизотропией ×8** на `minFilter`: вблизи пиксель остаётся честно крупным, а вдаль текстура
  уменьшается корректно. Без мипмапов на один пиксель экрана приходился десяток текселей, и на бегу пол со стенами кипели рябью —
  это и выглядело как «низкий fps». Порог `alphaTest` у спрайтов снижен до ~0.25: усреднённая по мипмапам альфа иначе съедала
  тонкие силуэты вдали.
* Электрон: включена GPU-растеризация, отключён backgroundThrottling. На Deck запуск через Steam как Linux-приложение (target `dir`/AppImage).

## Оружие от первого лица

Отдельная сцена `ViewModel` рендерится после основной с очищенным depth-буфером — модели не залезают в стены и не режутся
геометрией. Меч (клинок, гарда, рукоять), латная рука (предплечье с пластинами, перчатка, красный рукав), пистолет, дробовик с
помпой, ракетница и сапог собраны из примитивов Three.js; анимации — по фазам замаха игрока (slash, heavy, finisher, kick, shoot, raise, reload).
Клинок краснеет от крови (`bloodOnBlade`). Своя модель: `public/models/<sword|pistol|shotgun|rocket>.glb` (метры, клинок вдоль +Y от
кулака, ствол вдоль −Z) подменяет процедурную при старте.

Пистолет и дробовик стреляют лучом сразу (`Player.shoot`), ракетница — снарядом: `WEAPONS.rocket.projectile`
переводит выстрел в `Rockets.fire` (`src/engine/rockets.js`). Ракета шагает по полметра за кадр и проверяет
врагов, стены и высоту пола (пол лучом не ловится), взрыв раздаёт урон с линейным падением до `radius`,
тип урона — `explosion`, зона попадания смещена в конечности, оглушения нет (кроме крита раз
на тридцать попаданий); за стеной волна слабеет до трети. Герою достаётся `selfDmg` и толчок — рокет-джамп.
Взрыв бьёт по ощущениям, а не только по здоровью: камера дрожит (`Player.addShake`, «травма»
0..1.2 гаснет за полсекунды и в кадре превращается в дрожь по трём осям и подскок камеры —
чем ближе взрыв, тем сильнее, а слышно её вчетверо дальше радиуса поражения), из точки
попадания вылетают обломки стены, а всё, что уже лежало рядом, расшвыривает волной
(`Gore.blast` — новых объектов не создаёт, будит лежащие куски).
Корпуса ракет и клубы дыма лежат в пулах, созданных при старте: в кадре модуль не создаёт ни объектов,
ни источников света (светит пулом вспышек `FX.light`) — иначе каждый выстрел заставлял бы three.js
пересобирать шейдеры всей сцены, а дым давал бы десятки лишних вызовов отрисовки.

## Управление

Мышь + WASD, 1–4 — меч / пистолет / дробовик / ракетница, Tab — режим рук, Q и колесо — перебор стволов, стрелки для поворота без мыши, геймпад (Steam Deck): левый стик — движение, правый — обзор, RT — правая рука (выстрел / удар мечом), LT — левая рука (в режиме ствола тоже стреляет, иначе бьёт клинком), A — прыжок, B — рывок, Y — смена ствола, X — перезарядка, LB — действие, RB — добить, нажатие стика — пинок, крестовина — 1–4 оружие, Select — режим рук, Start — пауза. Сборка и запуск на Deck — [DECK.md](DECK.md).

## Камера

Три оси: yaw/pitch от мыши, roll — наклон при стрейфе, отдача и удары дают отдельный kick по roll/pitch, рывок и выстрел толкают FOV. Есть покачивание при ходьбе и присед при приземлении.

## Разделка

* Каждый удар: струя капель по направлению удара + брызги на ближайшую стену по лучу + пятно на полу.
* Измотанный враг (здоровье ниже порога «Добивание» из настроек — по умолчанию 10 %, с оторванной конечностью — вдвое выше) входит в **смертельный стаггер**: пульсирует красным, стоит на месте и **умирает от любого следующего попадания**. Пинок и удар о стену тоже сбивают с ног, но такой боец цел и красным не горит. `F` рядом — **казнь**: камера доворачивается, меч поднимается двумя руками, замедление времени, голова отлетает гибсом с кровавым шлейфом, из шеи бьёт фонтан, тело стоит секунду и падает **безголовым трупом**, лечение +30.
* **Хедшот** из пистолета (верхние 22 % цилиндра): череп, мозг, глаз разлетаются, тело шатается без головы и падает.
* **Перебор урона** (тяжёлый третий удар комбо, пинок в стену, добивание в упор) — тело **разрывается**: руки, ноги, торс, рёбра, кишки, голова летят отдельно, оставляя следы и брызги при ударах о стены/пол.
* Пинок (`ПКМ`) отбрасывает; впечатанный в стену враг получает 45 урона и брызги на стене.
* **Броня** (`stats.armor`, 0…0.85): крупные твари держат корпусом часть урона — `demon` 0.25, `knight` 0.35, `baron` 0.45. Пробивается дробью в упор, тяжёлым замахом и попаданием в голову; крит дробовика и удар о стену её игнорируют.
* Трупы — **объёмные груды**: мятые низкополигональные комки в цветах одежды, кожи и мяса, слитые в одну геометрию (один draw call), рядом лежат отрубленные конечности, под всем растёт лужа. Пул на 40 груд.

## Враги: свои рисунки и анимации

Каждый враг описан своей папкой `public/enemies/<name>/`: `enemy.json` + `sheet.png` (лист кадров × вариантов внешности),
рядом его вещи (`drops/`) и, если нужно, свои куски тела (`gibs/`).
Там же боевые настройки и углы захода `flank`. Формат — в [ENEMIES.md](ENEMIES.md). Процедурные листы экспортируются
командой `npm run sheets`. Ближники не идут в лоб: выбирают угол захода (сбоку, со спины), идут к точке рядом с игроком
по A*, а под взглядом уходят по касательной; стрелки занимают позицию на дистанции под тем же углом.

## Уровни как данные

Уровень — JSON в `public/levels/<id>.json` (см. [EDITOR.md](EDITOR.md)): объекты (примитивы и префабы из `prefabs.js`),
враги, предметы, NPC, триггеры и правила с действиями. `levelloader.js` строит из него мир и исполняет логику;
`levelstore.js` знает, откуда брать уровень (проект / браузер / папка пользователя в Electron) и куда сохранять.
Смена уровня — `game.loadLevel(id)`: старый мир и враги удаляются, строится новый, герой переносится со здоровьем и оружием.
Хаб (`index.html`), игра (`game.html`) и редактор (`editor.html`) — три страницы одной сборки Vite; Electron отдаёт `dist/`
через схему `app://`, чтобы работал `fetch` JSON-файлов.

## Структура

```
index.html / src/hub      хаб: уровни, режимы, настройки
game.html  / src/main.js  игра: цикл, рендер, экраны, загрузка уровней
editor.html/ src/editor   редактор карт
src/sandbox/sandbox.js    панель песочницы (F1)
src/engine/levelloader.js JSON → мир, триггеры, правила, действия
src/engine/levelstore.js  где лежат уровни и как сохраняются
src/engine/prefabs.js     составные объекты (хижина, ванна, машина…)
src/engine/settings.js    схема настроек игры
src/main.js            цикл, рендер, экраны
src/engine/world.js    геометрия, коллизии, лучи, навигация
src/engine/textures.js процедурные текстуры и декали
src/engine/sprites.js  персонажи, гибсы, трупы, предметы
src/engine/player.js   контроллер, камера, оружие
src/engine/enemies.js  ИИ, урон, смерть, казнь
src/engine/gore.js     капли, гибсы, декали, трупы
src/engine/fx.js       искры, трассеры, вспышки
src/engine/rockets.js  ракеты: полёт снаряда, взрыв по площади, отдача взрывом
src/engine/viewmodel3d.js оружие от первого лица в 3D (отдельная сцена поверх, GLB-подмена)
src/engine/audio.js    синтез звука (без музыки и шагов)
src/ui/hud.js          HUD, кровь на экране, сообщения
public/levels/*.json   уровни (сейчас только sandbox — песочница)
electron/main.cjs      оболочка Steam
```

## Команды

```
npm run dev        # dev-сервер на http://localhost:5173
npm run build      # сборка в dist/
npm run electron   # сборка и запуск в Electron (полный экран)
npx electron . --windowed --log   # окно 1280×800 и консоль рендерера в терминал
npm run dist:mac   # пакет для macOS в release/ (аналогично --win/--linux)
```

Замеры в браузере (Chromium, внутренний рендер 0.5×): 18 draw call'ов, ~6 тыс. треугольников в кадре в разгар боя, кадр упирается в vsync (120 fps на 120 Гц). Steam Deck при 640×400 внутреннего разрешения держит 60 fps с большим запасом; при желании `P` переключает 0.75× и 1.0×.
